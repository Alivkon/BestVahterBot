Изменения: команда /add (только для администратора)

Дата: 06.11.2026  |  Проект: BestVahterBot  |  Шаг: добавление команды /add

1. Новая команда /add

  • /add слово1, слово2, ... — добавляет запрещённые слова в список фильтра.
  • Разделители: запятая, точка с запятой, перенос строки.
  • Только для администратора: проверяется message.from_user.id == ADMIN_CHAT_ID (ID из .env). Остальным — ответ «⛔ Эта команда доступна только администратору».
  • Дубликаты (без учёта регистра) пропускаются с пометкой «уже были в списке».
  • Бот отвечает отчётом: сколько слов добавлено, сколько пропущено, сколько всего слов в списке.

2. Персистентность добавленных слов

  • Новые слова сохраняются в data/extra_words.json (каталог смонтирован в контейнер как volume ./data:/app/data) — переживают перезапуск и пересборку контейнера.
  • Загрузка при старте: load_extra_words(), сохранение — save_extra_words() (атомарная запись через .tmp + os.replace).
  • Базовый список forb_Words из bestvahterbot_words.py не изменяется — добавленные слова хранятся отдельно.

3. Регистронезависимый фильтр слов

Раньше проверка была регистрозависимой (word in message.text), из-за чего список слов дублировался в двух регистрах. Теперь:

  • При старте строится единый список FORBIDDEN: все слова приведены к нижнему регистру, дубликаты удалены (было 242 записи — стало 120 после схлопывания дублей).
  • Проверка: word in message.text.lower() — срабатывает на любой регистр.

5. Проверки

  • py_compile — компиляция без ошибок.
  • Тест логики внутри контейнера: построение FORBIDDEN, добавление слов, отсев дубликатов, запись/чтение extra_words.json.
  • Контейнер пересобран (docker compose up -d --build), бот запущен, polling активен.

6. Пример использования

/add новый спам словосочетание, ещё слово
✅ Добавлено слов: 3 (новый спам, словосочетание, ещё слово)
📋 Всего слов в списке: 216

Примечание: после правки кода не забывать docker compose up -d --build. Слова, добавленные через /add, живут в volume и пересборки не требуют.
