Подготовка сервиса к работе в контейнере

Дата: 13.11.2026  |  Проект: BestVahterBot

Изменения

  • Контейнер запускается с минимальными привилегиями: отключены Linux capabilities, включён no-new-privileges, установлен лимит процессов.
  • Корневая файловая система контейнера переведена в режим только для чтения; временный каталог /tmp предоставляется через ограниченный tmpfs.
  • Добавлен процесс-init для корректного завершения дочерних процессов и увеличен период graceful shutdown.
  • Настроен вывод логов Python в stdout без создания bytecode-файлов.
  • Документация описывает `.env`, постоянный volume `data/` и требуемый UID 1001 для доступа к данным.

Изменённые файлы

ФайлИзменение
DockerfileДобавлены runtime-переменные Python; запуск остаётся от непривилегированного пользователя.
docker-compose.ymlДобавлены ограничения безопасности, read-only root filesystem, tmpfs, init и grace period.
README.mdДобавлены требования к конфигурации и правам на volume.

Проверки

  • docker compose config --quiet — успешно.
  • docker compose build bestvahter-bot — образ собран успешно.
  • Права каталога `data/` соответствуют UID 1001; volume доступен для записи пользователю контейнера.
  • Одноразовый запуск контейнера с переопределённой командой подтвердил доступ к SQLite: прочитано 120 слов.
  • Основной процесс бота и polling Telegram не запускались.

Запуск: после проверки `.env` выполните `docker compose up -d --build`, затем проверьте состояние через `docker compose ps` и логи через `docker compose logs -f bestvahter-bot`.
